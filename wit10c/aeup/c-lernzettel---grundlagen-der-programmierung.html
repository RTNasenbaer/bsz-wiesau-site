C# Lernzettel: Grundlagen (AEuP)

1 Konsolenprojekt und Grundgerüst

  • Visual Studio: Neues Projekt → Konsolen-App (C#) → Name vergeben → Erstellen
  • Starten: F5 (mit Debugger) oder Strg + F5 (ohne Debugger)

Kommentare

  • Einzeilig: // Kommentar
  • Mehrzeilig: /* Kommentar */
  • Kommentare werden vom Compiler ignoriert.

Anführungszeichen und Literale

  • "Text" = doppelte Anführungszeichen → string
  • 'x' = einfache Anführungszeichen → char
  • Kommazahlen mit Punkt schreiben: 1.25
  • Endungen: f = float, m = decimal, L = long

Welchen Typ nehme ich?

  • Rechnen mit ganzen Zahlen → int
  • Rechnen mit Kommazahlen → double (Geld: decimal)
  • Zahlen, mit denen man nicht rechnet (Telefonnummer, PLZ, Hausnummer) → string, denn führende Nullen und +49 gehen sonst verloren
  • Ja/Nein-Information → bool

3 Variablen

Bezeichner (Name):

  • erlaubt: Buchstaben, Ziffern, _
  • nicht mit einer Ziffer beginnen, keine Leerzeichen, kein Schlüsselwort (z. B. byte, int)
  • Groß-/Kleinschreibung zählt, üblich ist camelCase: zahlDerVersuche
VorgangSyntaxBeispiel
DeklarierenTyp name;int alter;
Initialisierenname = Wert;alter = 28;
Beides gleichzeitigTyp name = Wert;int alter = 28;
Mehrere gleichen TypsTyp a, b;int x, y;

Reihenfolge

Immer erst der Typ, dann der Bezeichner: int alter;, nicht alter int;
Der Wert steht rechts vom =: char c = 'A';, nicht char 'A' = c;

5 Eingabe und Typkonvertierung

Console.ReadLine() liefert immer einen string. Für Zahlen muss konvertiert werden.

Von → NachBefehl
string → intint.Parse(s) oder Convert.ToInt32(s)
string → doubledouble.Parse(s) oder Convert.ToDouble(s)
Zahl → stringzahl.ToString()

FormatException

Ist der Text keine gültige Zahl (z. B. "abc"), stürzt das Programm mit einer FormatException ab.

Sicherer: TryParse (nicht besprochen, aber sinnvoll)

Rückgabe true/false zeigt, ob die Umwandlung geklappt hat. Vorher mit if prüfen.

Implizit und explizit

  • Implizit (automatisch, kein Datenverlust): kleiner → größer, z. B. short → int, float → double, int → long
  • Explizit (Cast, Verlust möglich): größer → kleiner, Typ in Klammern davorsetzen

Rangfolge laut Unterricht: decimal > double > float > long > int > short > byte

8 Kurz-Checkliste

  • Typ vor Bezeichner, Wert rechts vom =
  • "…" für string, '…' für char
  • Dezimalpunkt statt Komma im Code
  • Zahlen ohne Rechenzweck → string
  • ReadLine() gibt immer string zurück → konvertieren
  • Jede Anweisung endet mit ;
